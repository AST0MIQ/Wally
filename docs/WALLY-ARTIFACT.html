เข้าสู่ระบบ

ยืนยันตัวตนด้วย Google และตรวจสิทธิ์บนเซิร์ฟเวอร์

ผู้เยี่ยมชม
เข้าสู่ระบบด้วย Google
Google OAuth → Auth.js
สร้างผู้ใช้และหมวดหมู่เมื่อเข้าใช้ครั้งแรก
ตรวจ session → ภาพรวม

ใช้ Auth.js v5 และ Prisma Adapter เก็บ session ในฐานข้อมูล ไม่ได้ใช้ JWT เป็นกลยุทธ์ session หลัก ไม่มีฟอร์มสมัครด้วยรหัสผ่านของ Wally และยังไม่มี Apple Sign-In

เส้นทางที่ต้องยืนยันตัวตน

Middleware ตรวจว่ามีคุกกี้ก่อน ส่วน requireUser ตรวจ session จริงฝั่งเซิร์ฟเวอร์สำหรับ /dashboard, /transactions, /accounts, /portfolio, /analytics, /reports และ /settings ส่วน /admin ใช้ requireAdmin เพิ่มเติม มี action ออกจากระบบ

ยังไม่พบ route /onboarding ตาม flow ในร่างสถาปัตยกรรม การสร้างหมวดหมู่เริ่มต้นทำใน createUser event

13 / WALLY

ความปลอดภัย

หลักการที่พบในโค้ด พร้อมขอบเขตที่ควรรู้

ตัวตนและสิทธิ์

Google OAuth, database sessions, server guards และการตรวจเจ้าของบัญชี/รายการด้วย userId จาก session ปิดการเชื่อมบัญชี Google ด้วยอีเมลแบบอันตราย

ตรวจข้อมูลก่อนบันทึก

Server Actions หลักใช้ Zod และ rate limit; มี idempotency key ลดการสร้างซ้ำ, soft delete และ AuditLog สำหรับการทำรายการ

การป้องกันระดับเว็บ

ตั้ง CSP, HSTS, X-Frame-Options, nosniff และ Referrer-Policy ใน Next.js; API export ใช้ no-store และไม่ส่ง OAuth tokens/session ออกในชุด export

ขอบเขตปัจจุบัน

Rate limiter อยู่ในหน่วยความจำของแต่ละ instance ไม่ใช่ตัวนับร่วมข้ามเซิร์ฟเวอร์ CSP ยังอนุญาต inline scripts/styles ไม่พบการบังคับ RLS ใน migration ที่ตรวจ

ส่วนนี้อธิบายการทำงานจากโค้ด ไม่ใช่ผลการตรวจสอบความปลอดภัย (security audit) หรือการรับรองระบบ production ไม่มีการแสดงข้อมูลลับหรือค่าการตั้งค่าส่วนตัวในไฟล์นี้

อ้างอิงโค้ด: src/server/lib/action.ts · guards.ts · rate-limit.ts · src/server/services/export.service.ts · next.config.ts · prisma/migrations/

16 / WALLY

ตารางความสามารถ

แยกสิ่งที่ทำแล้ว สิ่งที่ทำบางส่วน และสิ่งที่อยู่ในแผน

“มีในโค้ด” หมายถึงตรวจพบ implementation ไม่ใช่การรับรองการทำงานของบริการที่เปิดใช้อยู่

ความสามารถสถานะหมายเหตุ
เข้าสู่ระบบ Googleมีในโค้ดมี OAuth และ database sessions; ต้องตั้งค่าจริง
ภาพรวม / รายการ / บัญชีมีในโค้ดหน้า UI และ service คำนวณยอด
โอนเงิน / หลายสกุลเงินมีในโค้ดต้นทาง–ปลายทาง จำนวนเงินสองสกุล และ FX
หมวดหมู่ / หมวดหมู่ย่อยมีในโค้ดสร้าง แก้ไข ลบ และ seed ให้ผู้ใช้ใหม่
พอร์ตลงทุน / ราคาหลักทรัพย์มีในโค้ดBUY/SELL, ต้นทุนเฉลี่ย, Finnhub cron, ราคาเอง
วิเคราะห์มีในโค้ดเปรียบเทียบรายเดือนและแนวโน้มหมวดหมู่
ผู้ดูแลระบบมีในโค้ดสถิติผู้ใช้และกราฟการสมัคร
ภาษาไทย / อังกฤษ / โหมดมืดมีในโค้ดมีไฟล์แปลและตัวสลับใน UI
หน้าจอปรับตามขนาดมีในโค้ดsidebar เดสก์ท็อป / เมนูล่างมือถือ
PWAบางส่วนมี manifest/worker; การติดตั้งและออฟไลน์จริงยังไม่ยืนยัน
ส่งออก JSON / ลบบัญชีตนเองมีในโค้ดมีหน้า Settings/Data และ API/action
กู้คืนรายการที่ลบบางส่วนมี action สำหรับ Transaction; ยังไม่มี UI กู้คืน
ตั้งค่าโปรไฟล์ / สกุลเงินหลัก / timezoneบางส่วนมีฟิลด์ใน User; หน้า Settings ปัจจุบันไม่ครบตามร่าง
รายงานอยู่ในแผนมี route แต่เป็น placeholder
Apple Sign-Inอยู่ในแผนระบุ P1; provider ปัจจุบันมี Google
รายการประจำบางส่วนมี RecurringRule schema; scheduler/UI ยังไม่มี
งบประมาณ / เป้าหมาย / นำเข้า CSVอยู่ในแผนระบุ P2 ในเอกสาร ยังไม่พบการทำงาน
ปันผล / แตกหุ้นอยู่ในแผนอยู่ในแผน P2
บันทึกออฟไลน์และซิงก์ยังไม่มีไม่พบ queue หรือระบบซิงก์รายการ
ความต่างระหว่างเอกสารกับโค้ดที่พบ
  • ARCHITECTURE ยังขึ้น DRAFT / ยังไม่เริ่มทำ แต่มีฟีเจอร์หลักแล้ว รวมถึงโหมดมืดและ Analytics ที่เดิมอยู่ P1
  • ร่างเมนูล่างระบุ Portfolio แต่โค้ดปัจจุบันใช้ Accounts
  • ร่างมี /onboarding แต่ยังไม่พบ route นี้ การสร้างหมวดหมู่ทำผ่าน auth event
  • UI-REDESIGN ระบุว่าลบ preview route แล้ว แต่ยังพบ src/app/ui-preview/page.tsx พร้อมข้อมูลสมมติ
  • เอกสารเลือก Neon driver adapter แต่ package.json และ db.ts ใช้ PrismaClient ปกติ
  • README ระบุ PWA เป็น Phase 4 แต่มี Serwist และ manifest แล้ว สี manifest ยังเป็น indigo #4f46e5 ขณะที่สีหลัก UI ปัจจุบันเป็น blue #2563eb

อ้างอิงโค้ด: docs/ARCHITECTURE.md · docs/UI-REDESIGN.md · README.md เทียบกับ src/ และ package.json

หมายเลขอ้างอิง dependency ranges ใน package.json กราฟแอปใช้คอมโพเนนต์ที่เขียนเอง เอกสารไฟล์นี้ใช้ HTML + CSS + JavaScript ธรรมดา ไม่มี React runtime, CDN, backend หรือขั้นตอน build
